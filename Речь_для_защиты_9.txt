2. КРАТКОЕ ВСТУПЛЕНИЕ (40–50 сек)

Здравствуйте. В лабораторной работе № 9 я закрыла сквозной проект
гостиницы: браузерный клиент ходит в REST API из прошлой работы,
API пишет в SQLite.

Клиент — Blazor Web App в режиме Interactive Server.
Интерфейс называется Aurelia. Это не отдельная предметная область,

Рядом лежат тесты сервисного слоя и один интеграционный тест

3. ПОЧЕМУ ИМЕННО ТАКАЯ МОДЕЛЬ BLAZOR

В .NET 8 есть три модели.

Blazor Server держит состояние на сервере, браузер получает diff
по SignalR. Удобно, когда HttpClient должен звать API с сервера.

Blazor WebAssembly качает .NET в браузер. HttpClient тогда идёт
из браузера, и нужен CORS.

Blazor Web App — шаблон .NET 8, который собирает обе модели.
Я взяла Interactive Server на всё приложение и отключила prerender:
так ProtectedSessionStorage с JWT не вызывается до появления
JavaScript, и сессия после обновления страницы восстанавливается.

Компоненты — файлы .razor. Разметка и блок @code в одном файле.
Параметры передаются как [Parameter], общий признак зрителя —
через [CascadingParameter]. Привязка — @bind и @bind-Value.
Событие наверх — EventCallback<T>. Службы приходят через @inject.
Страницы открываются по @page, переход делает NavigationManager.
Формы — EditForm и DataAnnotationsValidator.

5. ЧТО УМЕЕТ ЭКРАН

Без токена: главная и каталог номеров.
С ролью Guest: свои брони, создание брони на себя, отмена активной.
С ролью Admin: номера целиком, все брони, статусы, удаление,
гости — создание, правка, удаление.

Гостей в API лабораторной № 7–8 можно было только читать и создавать.
Для полного CRUD я добавила PUT и DELETE /api/guests.
Удаление гостя или номера с бронями по-прежнему конфликт 409:
связь Restrict не обходится.

Цена на карточке номера — прикидка: ночи умножаются на цену.
Итог в ответе считает BookingService. Клиент это правило не подменяет.


6. ЧТО ПОКАЗАТЬ В КОДЕ

• Модель хостинга: HotelBlazor/Program.cs
  AddRazorComponents().AddInteractiveServerComponents()
  и в App.razor InteractiveServerRenderMode(false) — без prerender.

• Параметр и каскад: Components/Shared/RoomCard.razor
  [Parameter] Room, [Parameter] EventCallback<RoomModel> Selected,
  [CascadingParameter] Viewer.
  Каскад отдаёт MainLayout.

• Привязка: Rooms.razor, поля фильтра через @bind.
  Login.razor, InputText @bind-Value.
  RoomDetails.razor, InputDate @bind-Value и живой пересчёт суммы.

• Форма: RoomForm.razor
  EditForm, DataAnnotationsValidator, ValidationMessage.
  Пустой номер не уходит на API.

• HttpClient: HotelApiClient получает клиент из IHttpClientFactory
  и перед запросом ставит Bearer, если AuthSession уже держит токен.

• Жизненный цикл: RoomDetails.OnParametersSetAsync
  перечитывает номер, если изменился Id.
  MainLayout.OnAfterRenderAsync один раз достаёт токен из браузера.

• Маршрут и роли: RoomForm.razor
  две директивы @page и [Authorize(Roles = "Admin")].
  Атрибут читает маршрутизатор. На HTTP-запросе токена ещё нет:
  он в браузере, не в cookie. Поэтому AllowBlazorToDecide
  пропускает запрос дальше, а экран «войдите» или «недостаточно прав»
  рисует уже AuthorizeRouteView.

• Тест бизнес-правила: BookingServiceTests,
  метод Create_multiplies_room_price_by_nights.
  Это [Theory] и [InlineData]: 1 ночь — 85, 3 — 255, 10 — 850.
  Репозитории заменены Moq. В AddAsync перехватывается сущность,
  которую собрал сервис, и проверяется TotalPrice.
  Так проверяется сервис, а не заглушка.

• Интеграционный тест: ApiFlowTests и HotelApiFactory.
  WebApplicationFactory<Program> поднимает настоящий хост.
  Для этого в конце Program.cs API объявлен public partial class Program.
  Ключ JWT и файл SQLite тест подставляет сам, user-secrets не нужны.

• Docker: HotelApi/Dockerfile, строки FROM sdk AS build
  и FROM aspnet AS final. В финальный образ не входит компилятор.

• CI: .github/workflows/ci.yml
  триггер push и pull_request, job build-test-publish,
  затем job docker.

8. ОТВЕТЫ НА ТИПИЧНЫЕ ВОПРОСЫ

Чем Blazor Server отличается от WebAssembly?
Server выполняет компоненты на сервере, в браузер идёт разница
по SignalR. WebAssembly исполняет их в браузере.
У меня Interactive Server: HttpClient вызывает API с сервера,
поэтому браузеру не нужен CORS. CORS в API всё равно расширен
адресом клиента http://localhost:5280.

Зачем IHttpClientFactory, если есть new HttpClient()?
Фабрика переиспользует сокеты и задаёт базовый адрес в одном месте.
HotelApiClient просит именованный клиент "hotel".
Адрес в Docker другой: http://api:8080, его подставляет переменная
Api__BaseUrl. Код клиента не меняется.

Где лежит JWT?
В памяти circuit и в ProtectedSessionStorage вкладки.
Это не открытый localStorage: ASP.NET шифрует значение ключом
приложения. На странице токен не показывается.
После «Выйти» хранилище очищается.

Чем 401 отличается от того, что видно на экране?
401 и 403 приходят с API как ProblemDetails.
Клиент читает detail или errors и пишет текст над формой.
Если роли не хватает ещё до запроса, AuthorizeRouteView
показывает «Недостаточно прав» и на API запрос не уходит.

Почему тесты сервиса, а не только строк?
Цена, пересечение дат, запрет чужой брони и запрет удалить
занятый номер — это BookingService, RoomService и GuestService.
Репозиторий заменён Moq, часы заменены FixedClock,
чтобы «сегодня» не плавало. Утилиту форматирования денег я не
считаю за эти тесты.

Что делает интеграционный тест?
WebApplicationFactory поднимает Program API.
База — временный файл SQLite, ключ JWT задан в памяти,
в репозиторий он не пишется. Сценарий: GET /api/rooms без токена,
логин admin, POST номера, логин ivanov, POST номера ждёт 403.

Почему Docker в два этапа?
Первый этап — SDK, он компилирует. Второй — aspnet, в нём только
опубликованные dll. Образ меньше, и компилятора в проде нет.
Compose связывает web с api по имени службы, а не через localhost.

Что делает GitHub Actions?
По push и pull request в ветки lab-9, main и master:
restore, build, test, publish API и Blazor в артефакт,
затем docker compose build. Секрет подписи в workflow для тестов
не нужен: фабрика теста задаёт ключ сама.
Демо-ключ в docker-compose нужен только чтобы контейнер стартовал
на защите. В appsettings.json ключа нет.

Почему у гостя нельзя удалить бронь?
Так решено в API: гость меняет статус только с Active на Cancelled
и только у своей брони. Удаление закрыто политикой AdminOnly.
Клиент прячет кнопку, но даже если её вызвать, API ответит 403.
