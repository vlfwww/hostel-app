─── 1. Номера ───
«Список номеров читается через EF Core, AsNoTracking — только просмотр.»

─── 2. Гости ───
«Гости подгружаются вместе с профилем Include — связь one-to-one.»

─── 3. Бронирования ───
«Бронь + гость + номер + услуги: Include / ThenInclude

─── 4. Регистрация гостя ───
«Создание через DbContext.Add и SaveChanges. Вместе с гостем

─── 5. Цена номера ───
«Изменение сущности в контексте и SaveChanges — обычный UPDATE.»

─── 8. Поиск по типу ───
«Тот же поиск, но уже ADO.NET: тип передаётся параметром $type,

«В одной транзакции: бронь + услуга «Завтрак» + номер становится занятым.

7. ОТВЕТЫ НА ТИПИЧНЫЕ ВОПРОСЫ

Чем ADO.NET отличается от EF Core?
ADO.NET — сами пишем SQL (Connection/Command/Reader).
EF Core — ORM: объекты C#, LINQ, ChangeTracker, миграции.

Что такое Code First?
Сначала сущности и DbContext в коде, потом миграции создают схему БД.

Зачем параметры в SQL?
Чтобы ввод пользователя не стал частью текста SQL (анти-injection).

Что делает ChangeTracker?
Следит за Added / Modified / Deleted / Unchanged и строит SQL при SaveChanges.

Что такое N+1 и как лечить?
1 запрос за список + по запросу на каждую связь.
Лечится Include / ThenInclude (как в пункте 3 меню).

Cascade vs Restrict?
Cascade — дети удаляются с родителем (профиль с гостем).
Restrict — нельзя удалить родителя при наличии броней.
